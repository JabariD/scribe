# Scribe

macOS voice-to-text app. Tauri + React + Rust.

## Structure
```
src/App.tsx              # React UI, recording state
src-tauri/src/main.rs    # Rust: commands, OpenAI API, tray, hotkeys
src-tauri/src/audio.rs   # 16 kHz resampling and WAV I/O shared by all engines
src-tauri/src/local.rs   # On-device Parakeet engine: download, chunked + live transcription
src-tauri/src/realtime.rs # OpenAI realtime websocket transcription
```

## Commands
```bash
npm run tauri dev        # Dev mode
npm run tauri build      # Build .app
cd src-tauri && cargo test  # Rust tests
```

## Key Patterns
- Global hotkey registered in Rust, emits event to frontend
- Transcription provider is `openai` or `local`. Every path produces a raw transcript, then `finalize_transcript` applies optional OpenAI cleanup; in-recording failures (OpenAI realtime or local live session) fall back to the saved WAV
- Local engine: NVIDIA Parakeet TDT 0.6B v3 int8 via `transcribe-rs` (ONNX Runtime, CPU, statically linked). Chosen over Whisper large-v3-turbo for better English accuracy and speed; the trade-off is no vocabulary prompt. Files are pinned to a Hugging Face commit and SHA-256 verified on download into `~/Library/Application Support/scribe/models/`
- Parakeet slows sharply on long clips (M3 Pro: 27 s → 0.95 s, 155 s → 10.6 s whole-clip), so audio is cut into ≤30 s chunks at the quietest pause, and while recording the local session transcribes finished chunks so stopping waits only for the last one (~1 s at any length). The model loads at record start and unloads after 10 idle minutes. Benchmarks: ignored tests in `local.rs`
- Recordings are resampled to 16 kHz before saving: a third of the upload size for OpenAI and the rate both engines expect. Max recording is 750 s (OpenAI 25 MB upload cap)
- One shared `reqwest` client; `prewarm_openai_connection` opens the TLS connection at record start so the upload after stop skips the handshake
- Single hidden Tauri window is reused for both settings and the optional recording overlay HUD
- The window is transparent, which on macOS needs `macOSPrivateApi` (config + `macos-private-api` Cargo feature); without it WebKit paints a white box around the overlay pill. Native shadow is on for settings and off for the pill (`set_window_shadow`), which draws its own CSS shadow
- UI sounds are generated by `src-tauri/sounds/generate.py`, embedded in the binary, and played with preloaded `NSSound` on the main thread
- Recording overlay can be disabled; when disabled, dictation stays minimized unless Scribe needs attention
- Tray icon: `src-tauri/icons/icon.png` is a transparent monochrome macOS template image (`iconAsTemplate: true`). Do not replace it with a full-color or opaque app icon, macOS renders its alpha silhouette as a solid menu-bar shape.
- Tray status: 🔴 recording, ⏳ processing, ✅ success, ❌ error
- Audio saved to `~/Library/VoiceTranscripts/`; timestamped Scribe WAVs are pruned using the transcript-history retention setting (0 keeps them indefinitely)
- API key stored in macOS Keychain (`com.scribe.app` / `openai-api-key`)
- Settings stored in `~/Library/Application Support/scribe/config.json` (`show_recording_overlay`, `realtime_transcription_enabled`, `prompt`, `post_process_enabled`, `post_process_prompt`, `transcription_provider`; legacy `api_key` is migrated to Keychain on read)
- Transcript history is stored locally in the Tauri webview `localStorage`; its user-configurable day-based retention also applies to timestamped Scribe WAVs
